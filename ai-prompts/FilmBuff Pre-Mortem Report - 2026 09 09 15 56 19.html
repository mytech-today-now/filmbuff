Executive Summary

The most urgent risks cluster around command honesty and data freshness. Several paths can hide unreadable input, stale cache state, or partial-success outcomes as if they were clean success.

A second cluster sits in module identity and linked-state handling. The CLI sometimes uses canonical full names, sometimes exact matches, and sometimes raw config entries, which can make the same module look linked in one place and unlinked in another.

The remaining risks are lower in priority but still operationally important. They include parser ambiguity, module discovery stability, documentation drift, and a few testable assumptions that need one more reproduction before the behavior is changed.

Three items are still testable assumptions: issues 10, 13, and 14.
